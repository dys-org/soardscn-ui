# Plan: soardscn Registry Structure

## Goal
Serve this repo as a shadcn-compatible registry with consumer namespaces:
- `@ui/*` -> `https://dys-org.github.io/soardscn-ui/r/ui/{name}.json`
- `@components/*` -> `https://dys-org.github.io/soardscn-ui/r/components/{name}.json`

Current source-of-truth layout:
- `src/registry/ui/*`
- `src/registry/components/*`
- `src/registry/lib/*` (internal shared helpers such as `utils`)

## Current architecture
1. Root manifest: `registry.json`
   - Maintained manually.
   - Read by `shadcn build`.
2. Build output: `public/r/*`
   - Generated by `pnpm registry:build`.
   - `scripts/organize-registry.mjs` groups output into:
     - `public/r/ui/*.json`
     - `public/r/components/*.json`
     - `public/r/lib/*.json`
3. Published registry entrypoint:
   - `public/r/registry.json`

## Dependency conventions
- `registry:ui` items reference shared helper via `registryDependencies: ["utils"]`.
- `registry:component` items are published under `/r/components/*`.
- Cross-item UI dependencies use namespaced ids (for example `@ui/button`).

## Consumer setup
Consumers should add this to `components.json`:

```json
{
  "registries": {
    "@ui": "https://dys-org.github.io/soardscn-ui/r/ui/{name}.json",
    "@components": "https://dys-org.github.io/soardscn-ui/r/components/{name}.json"
  }
}
```

Install examples:

```bash
pnpm dlx shadcn@latest add @ui/button
pnpm dlx shadcn@latest add @components/multi-select
```

## Verification steps
1. Run `pnpm registry:build`.
2. Confirm generated output exists in `public/r/ui`, `public/r/components`, and `public/r/lib`.
3. Confirm `public/r/registry.json` contains expected `registryDependencies` values (for example `"utils"`).
4. Verify local app still runs:
   - `pnpm dev`
   - `pnpm build`
